# Working notes for coding agents

Read `.claude/skills/` first. `validate-change` covers how to verify a change,
`tooling-invariants` covers what a change must not break, and `cut-a-release`
covers publishing. This file holds only the conventions that sit above those.

## Attribution

Nothing in this repository credits an AI assistant. That means:

- **Commits** are authored as the repository owner. No `Co-Authored-By` trailer
  naming an assistant, and no assistant name in the message body.
- **Pull requests and issue comments** carry no "Generated by" footer. Some
  tooling appends one automatically when a PR is created; remove it by editing
  the body afterwards, and check that it is gone rather than assuming.
- **Code comments, documentation and release notes** are written in the
  repository's voice, not signed.

`Test-Modpack.ps1` enforces this with the `no agent attribution committed`
check, so a footer that slips into a tracked file fails the build. The check
cannot see commit messages or PR bodies, so those stay a matter of care.

Naming a model in prose is not attribution. The vendored `sepia` skill
catalogues model fingerprints by name, and the `.claude/skills/` path is fixed
by the tooling; neither is a credit line.

## Reporting

Say which gate actually ran. The Pester suite needs Windows, so on Linux or
macOS the honest report is "the validator passed and the suite did not run",
never "tests pass". `Invoke-Tests.ps1` exits `3` to make that distinction
machine-readable. See `validate-change` for the full contract.

State what a check cannot tell you. A green CI run on a change the runner
cannot exercise confirms nothing broke, not that the change works.
